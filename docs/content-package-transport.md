# Premium package transport — prompt 19

Bieżący wynik: **PASS lokalnego promptu19 po residualu** — [odbiór przyjętego pakietu i iPhone17](#residual19--odbiór-lokalny-15102026). R04/usługi i wydanie pozostają odrębne. Poniższy wcześniejszy odbiór PARTIAL opisuje wersję przed dopuszczeniem tej oferty.

One production transport implementation (not deployed in this session): `GET /v1/content/packages/:trackId/:nodeId` authorizes App Check, Firebase account and a fresh RevenueCat entitlement, then returns `patternly-content-download-v1` JSON with `Cache-Control: private, no-store`. It rechecks identity availability and account authorization after signing. No API gzip stream or local-filesystem runtime fallback remains.

The descriptor contains the existing immutable manifest, `{bucket,path,generation}`, `downloadUrl` and `expiresAt`. GCS object metadata must match the content-addressed manifest path and compressed size, use `application/gzip` and have no Content-Encoding. The V4 GET signature includes that generation; lifetime is at most 60 seconds. A signed URL is a bearer capability: access already issued can remain usable until expiry. Do not persist or log it. A generation is a per-download object snapshot, not a new session pin or a stored Firestore manifest field. Path and SHA-256 hashes protect the immutable content identity.

The mobile adapter validates the exact descriptor and GCS URL/expiry, then downloads without account/App Check headers or cookies, rejects redirects, bounds the descriptor to 16 KiB and package to 2 MiB under one deadline. It maps the validated manifest to the existing verifier's metadata. The verifier checks gzip/artifact hashes and sizes, schema, semantics and expected offer identity before the existing immutable store/readback and atomic pointer activation. Profile generation fences apply to requests and before the synchronous pointer commit. Session exact pins and retained package history are unchanged.

## Prepared configuration, not deployed

- `CONTENT_PACKAGE_BUCKET`: private GCS bucket containing immutable `packages/<track>/<node>/<compressed-sha256>.gzip` objects.
- `CONTENT_PACKAGE_READINESS_TRACK_ID` and `CONTENT_PACKAGE_READINESS_NODE_ID`: a concrete admitted package, paired and requiring the bucket. `/ready` probes its Firestore pointer/manifest, GCS object metadata and signer, with a 3-second readiness deadline. Missing config, pointer, object or signer fails readiness; production also requires the RevenueCat reader. This is a service-level Premium readiness gate.
- `CONTENT_PACKAGE_LOCAL_ROOT` now fails configuration explicitly. `LocalFilesystemContentPackageStorage` is retained only for existing producer/tests, with no deployed route transport.
- Runtime uses existing Firebase Admin credentials and `firebase-admin/storage`; no new dependency/key file. Cloud Run service account needs object read on this private bucket and signing authority (`iam.serviceAccounts.signBlob`, normally via IAM Credentials on the signing service account). Enable IAM Credentials API as applicable. Runtime does not need bucket write, public object ACL or list privileges. Existing publisher tooling may separately use create-only writes; the GCS adapter uses `ifGenerationMatch:0`, checks existing bytes on conflict and verifies readback before pointer activation.
- Before any authorized rollout, admit a real Premium offer/payload and supply its readiness target; apply least-privilege IAM and verify real metadata/signing/download on the release candidate in R04. Do not set a smoke fixture as a production target. Keep checkout disabled until the remaining Premium gates pass.

## Evidence limits and reproduction

`node scripts/run-content-package-tests.mjs` runs real isolated Auth/Firestore route checks plus the production client/verifier/store/runtime on the existing explicit smoke producer output. GCS and local pointer are modeled; file readback is real Node filesystem. It checks exact session references, restart resolution, wrong hash, access denial, interrupted/offline download and profile switch. It does not prove producer admission, Expo native filesystem/MMKV, device behavior, IAM, GCS or store/RevenueCat services. No service changes/deployment are made.

The installed GCS SDK is separately probed with an ephemeral in-memory RSA key to establish the local V4 generation query/expiry contract. That is not provider acceptance. Official references: [V4 signed GET](https://docs.cloud.google.com/storage/docs/samples/storage-generate-signed-url-v4), [signing authority](https://docs.cloud.google.com/storage/docs/access-control/signing-urls-with-helpers).
